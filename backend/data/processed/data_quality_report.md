## 5. Text Normalization Decisions

### Guiding Philosophy: Conservative & Deterministic
Aggressive regex or text simplification destroys critical discriminative features in technical and professional resumes. Normalization preserves all domain tokens.

### Cleaning Transformations Applied (Variant A - Base Clean):
1. **HTML Entity Unescaping**: Unescaped standard entities (`&amp;` → `&`, `&lt;` → `<`, `&bull;` → space).
2. **Tag Stripping**: Removed any lingering `<...>` tags without altering enclosed content.
3. **Unicode NFKC Normalization**: Resolved ligatures (`ﬁ` `\ufb01` → `fi`, `ﬂ` → `fl`), fullwidth hyphens (`－` → `-`), and non-breaking spaces (`\xa0` → ` `).
4. **Control Character Removal**: Stripped non-printable ASCII `\x00-\x08`, `\x0b`, `\x0c`, `\x0e-\x1f`, `\x7f`, and soft hyphen `\xad`. Preserved `\n` and `\t`.
5. **Bullet & Marker Cleanup**: Normalized decorative symbols (`•`, `▪`, `◆`, `●`, `◦`, `❏`, `❖`, `➢`, `\uf0b7`, `\uf0a7`) to single whitespace.
6. **Quotes and Dashes**: Normalized curly apostrophes/quotes (`’`, `‘`, `“`, `”`) and dashes (`–`, `—`, `−`) to standard ASCII equivalents.
7. **Whitespace Standardization**: Normalized carriage returns (`\r\n` → `\n`), collapsed excessive blank lines (`\n{3,}` → `\n\n`), and collapsed multiple horizontal spaces.
8. **Technical Token Protection**: Preserved `C++`, `C#`, `.NET`, `SQL`, `Python`, `Java`, `AWS`, `Azure`, `GCP`, `TensorFlow`, `Node.js`, and all technical symbols.
9. **Section Header Preservation**: Retained section identifiers (`Summary`, `Experience`, `Education`, `Skills`, `Highlights`).

### Preprocessing Variants Implemented (in `backend/src/preprocessing.py`):
- **Variant A (Minimal)**: Deterministic normalization, case preserved, technical tokens preserved. (Used for baseline clean dataset).
- **Variant B (Conservative Cleanup)**: Lowercasing with strict protection of `C++`, `C#`, `.NET`, `Node.js` + noisy punctuation separator removal.
- **Variant C (Optional Stopwords)**: Conservative cleanup + curated stopword removal protecting technical keywords.

## 6. Joined-Word Investigation Findings
- **Hypothesis**: PDF extraction created joined words (e.g. `"inmultitasking"`, `"ableto"`, `"workethic"`).
- **Empirical Findings**:
  - Scanning `Resume_str` across all 2,484 records revealed that `"inmultitasking"` and `"workethic"` did not occur.
  - The single match for `"ableto"` occurred within the proper noun **`Ableton Live`** (digital audio workstation software used by sound designers).
  - Blind automated word splitting (e.g., splitting words containing common prepositions) causes severe false positive errors on technical software, libraries, and certifications (e.g., mutating `Ableton Live` → `Able to n Live`).
- **Conclusion**: Heuristic or regex-based word splitting was rejected to prevent dataset corruption. The conservative tokenizer and whitespace standardizer safely handle non-breaking spaces without altering tokens.

## 10. Known Dataset Limitations
1. **Class Imbalance**: Minor classes like `BPO` (22 records), `AUTOMOBILE` (36 records), and `AGRICULTURE` (63 records) have small sample sizes in validation and test splits (e.g., 3-4 records for BPO). Evaluation metrics must report macro-averaged F1 and per-class metrics alongside micro/weighted metrics in Phase 3.
2. **OCR / Formatting Noise**: Some resumes exhibit lack of sentence punctuation after bullet items. Conservative normalization standardizes whitespace without hallucinating punctuation.
